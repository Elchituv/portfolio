## The business question

PharmaDist (a fictional Israeli drug distributor) supplies hospitals, HMOs and pharmacies in five regions. In a hospital, a drug that arrives late or incomplete is a real problem, not an inconvenience.

**Question:** *"Sales are growing, but is service keeping up? Where do we fail to deliver on time and in full?"*

What makes it tricky: the ERP export is messy, and delivery performance has to be judged per **order** (an order only counts as a success if it arrived on time **and** every line was delivered in full), while sales are recorded per **order line**.

## Data

Four CSV files exported from the ERP (synthetic data, generated by `data_generator/generate_data.py`).

| File | One row = | Rows |
|---|---|---|
| `OrderLines.csv` | one product within an order | 73,619 (72,890 after cleaning) |
| `Orders.csv` | an order header: customer, dates, status | 12,075 |
| `Customers.csv` | a customer (hospital, HMO, pharmacy) | 140 |
| `Products.csv` | a product, with category and standard cost | 40 |

Orders run from 01/01/2024 to 30/09/2026 (the ERP extract date).

**Known quirks, found by profiling in Power Query on the entire data set:**

| Issue | Found | Fix in Power Query |
|---|---|---|
| Exact duplicate order lines (double export) | 437 rows | Remove Duplicates |
| Lines with quantity 0 (deleted in the ERP) | 292 rows | Filter `Quantity > 0` |
| Customer IDs typed in lower case or with spaces ("ghost customers": 156 distinct IDs for 123 real customers in the first 1,000 orders) | 362 orders | Trim + UPPERCASE |
| Region written 20 different ways for 5 regions (`NORTH`, ` north `…) | 28 customers | Trim + Capitalize Each Word |
| City with stray spaces and lower case (30 spellings for 22 cities) | 12 customers | Trim + Capitalize Each Word |
| Products with no category | 2 products | Replace with `Unclassified` |

## Solution process

1. **Profile before cleaning:** column quality and distribution on the **entire** data set, not the default first 1,000 rows.
2. **Clean in Power Query:** every fix is a recorded step, so it re-runs on every refresh.
3. **Merge the order header into the order lines:** one fact table at order-line grain, which gives a clean star schema.
4. **Model:** `FACT_Sales` with `DIM_Customer`, `DIM_Product` and a DAX `DIM_Date` (Auto date/time off). The date table ends at the extract date, so *2026 vs 2025* compares Jan–Sep with Jan–Sep. A second, **inactive** relationship on the delivery date is used via `USERELATIONSHIP`.
5. **Measures (DAX):** explicit measures for sales, margin, YTD, previous year and YoY % (`TOTALYTD` + `DATEADD`). OTIF is calculated **per order**: `AVERAGEX` over delivered orders, with context transition through `CALCULATE`.
6. **Reconcile:** every number on the report was checked against an independent SQL calculation (`sql/control_numbers.sql`).
7. **One page, ordered as a story:** KPIs, then the trend, then *where* service breaks, then *why*, then *what to do*.

## Results (January–September 2026)

| KPI | Value |
|---|---|
| Net sales | ₪54.9M, **+11.6%** vs Jan–Sep 2025 |
| Gross margin | **26.5%** (24.4% in 2025, 22.1% in 2024) |
| OTIF (on time and in full) | **73.4%**, against an 80% target |
| Orders that failed OTIF | 935 of 3,511: 530 incomplete, 325 late, 80 both |
| OTIF in the South | **62.7%**; Eilat 44.1% |
| On-time rate, South vs other regions | 77.4% vs 89.9–92.0% |
| Orders with antibiotics delivered in full, Nov 2025–Jan 2026 | 42–52% (vs ~95% in other months) |
| OTIF for HMOs (about half of sales) | 65.5% |

**Answer:** sales and margin are healthy, but service is not keeping up, and two different problems hide in one number. Most failed orders arrive **incomplete**: large HMO and hospital orders (8–9 lines each) fail if a single line is short, and antibiotics ran short in Nov–Jan. **Late deliveries** are concentrated in the South, worst in Eilat.

**Recommendation:** hold safety stock of key antibiotics and critical HMO/hospital items before winter, and fix the delivery schedule to the South, especially Eilat.

## Limitations

- The data is synthetic. The patterns are realistic, but the numbers describe no real company.
- The 80% OTIF target is an assumption for the example.
- OTIF is not additive: filtered by product category, an order is judged only on that category's lines, so every category can score above the overall total. That is correct, but it has to be explained.
- Sales are assigned to the **order** date. Open and cancelled orders carry no revenue.
- Next step: cost-to-serve per region, to price the fix for the southern routes.

## Feedback & iteration

Reconciling the report against the SQL control numbers caught three real problems:

- **Total sales ₪2,500.99 too high.** Power Query detects column types from the first 200 rows. All 2024 prices were whole numbers, so `UnitPrice` was typed *Whole Number* and every price from 2025 on was silently rounded. Fixed in the original *Changed Type* step. A fix added at the end does not help, because the decimals are already lost.
- **Regions listed twice (`center` and `Center`).** The model ignores upper/lower case but not leading spaces, so only the variants with a leading space stayed separate. Fixed with Trim + Capitalize Each Word.
- **"AVERAGEX cannot work with values of type String".** The flag columns had loaded as text. `OTIF %` hid the problem, because multiplying converts text to numbers automatically; `On-Time %` exposed it. The flags were retyped as Whole Number.

The first trend chart used two Y axes with different scales, which made the two years impossible to compare. It was replaced with a single axis and the year as the legend.

## How to run

- **Open the report:** `powerbi/PharmaDist.pbix` (Power BI Desktop, Windows).
- **Check the numbers:** from this folder, run `duckdb < sql/control_numbers.sql`.
- **Regenerate the data:** `python data_generator/generate_data.py data`. Add a seed (`... data 12345`) for a new version of the dataset.
