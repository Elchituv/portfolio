# מערך שיעור: "לקוחות רפאים", ניקוי נתונים ב-Power Query

| | |
|---|---|
| **משך** | 15 דקות |
| **קהל** | מסבי קריירה. בלי רקע טכני, אחרי היכרות ראשונה עם Power BI |
| **נדרש** | Power BI Desktop, התיקייה `data/`, דף התרגיל `exercise.md` |

## מטרות למידה
בסוף השיעור הלומדים יוכלו:
1. **לזהות** בעיות איכות בנתונים בעזרת Column profiling.
2. **לתקן** אותן ב-Power Query, כך שהתיקון רץ מחדש בכל רענון.
3. **לאמת** את התוצאה מול מספר ביקורת.

## דגשים להדגמה
- **Distinct מול Unique:** Distinct סופר כמה ערכים שונים יש. Unique סופר כמה ערכים מופיעים בדיוק פעם אחת. בעמודת מפתח, ערך Unique גבוה הוא סימן לשגיאות הקלדה, כי טעות קורית בדרך כלל פעם אחת.
- **מלכודת 200 השורות:** Power Query קובע את סוג העמודה לפי 200 השורות הראשונות. ב-2024 כל המחירים עגולים, ולכן העמודה UnitPrice מוגדרת כ-Whole Number, ומכאן כל המחירים מ-2025 מעוגלים בלי שום התראה. התוצאה היא פער של **2,500.99 ₪** בסך המכירות. זה הרגע שהלומדים זוכרים.
- **התיקון נעשה בצעד שבו נקבע הסוג.** צעד שמוסיפים בסוף לא מחזיר את האגורות שכבר נמחקו, בדיוק כמו שאי אפשר לחדד תמונה ששמרו באיכות נמוכה.

## שאלות לבדיקת הבנה
1. למה מנקים ב-Power Query ולא באקסל?
   **תשובה:** התיקון נשמר כצעד ורץ מחדש בכל רענון.
2. בעמודת מפתח יש 156 ערכי Distinct ו-34 ערכי Unique. מה זה אומר?
   **תשובה:** אותו לקוח נכתב בכמה צורות, ורוב הערכים שמופיעים פעם אחת הם שגיאות הקלדה.
3. סך המכירות שלכם יוצא גבוה ב-2,500 ₪. איפה תחפשו?
   **תשובה:** בסוגי העמודות, בצעד Changed Type הראשון.

## טעויות נפוצות ואיך מזהים אותן
| טעות | הסימן |
|---|---|
| הפרופיל מחושב רק על 1,000 השורות הראשונות | Count = 1000 |
| השורה הראשונה לא הוגדרה ככותרות (Use First Row as Headers) | ב-Region יש **21** ערכים במקום 20 |
| הסוג תוקן בצעד חדש בסוף, ולא בצעד המקורי | המספרים לא משתנים |
| לעמודה מחושבת לא הוגדר סוג | אין לידה Σ, ומופיעה השגיאה "cannot work with values of type String" |

- **לומדים שמתקשים:** לעבוד בזוגות, ולבדוק כל צעד מול טבלת היעדים שבדף התרגיל.
